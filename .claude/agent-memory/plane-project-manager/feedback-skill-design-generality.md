新しいSkillを設計する際、設計・調査の段階で特定のプロジェクト管理ツール（Plane）を前提にした実際のツール呼び出し（`list_work_item_types` / `list_work_item_properties` など）を行おうとしたところ、権限システム経由でユーザーから明確な拒否理由とともに拒否された。

ユーザーの発言（許可ダイアログ経由）:
「ある程度汎用的にしたいので、Skill作成時点では"Plane"を前提にしないでください(利用するタイミングでどのプロジェクト管理ツールを使うか未定のままSkillを作成したい)」

**Why:** Skillは複数のプロジェクト管理ツール（Plane以外も含む）に対応できる汎用設計を目指しており、設計・調査段階からPlane固有のAPI・データモデルに依存した調査を行うと、後で他ツールに差し替えにくい前提を埋め込んでしまうため。

**How to apply:** 「新しいSkillの設計のための事前調査」のような依頼が来た場合、実際にPlaneのMCPツールを呼び出して具体的なプロパティ定義やID等を調べる前に、まずその調査がSkill設計の前提を狭めないか（＝ツール非依存で進めるべきか）をユーザーに確認する。呼び出しが拒否された場合は無理に代替手段で回避せず、拒否理由をそのまま尊重して調査を打ち切り、依頼元に状況を報告する。
